Flagship · Research → library

sixdim-eval

My published paper, turned into a pip-installable Python library, CLI and GitHub Action that catch LLM output that looks finished but is missing, invented or overconfident.

  • Scores any LLM output against its source on six dimensions, with Claude, any OpenAI-compatible model, or a free offline heuristic judge.
  • Checks the judge against humans: quadratic-weighted kappa, exact and within-one agreement, true-positive and true-negative rates.
  • Gates CI: a prompt or model change that makes outputs worse fails the build.
  • paper/reproduce.py recomputes every published table from the raw data on every commit.

ResuMetric

A deployed FastAPI service that checks AI-generated CVs against their source material and flags anything missing or invented: a phone number, a degree classification, a "40% improvement".

  • Honest by design: the judge uses my paper's MISSING instruction, and the overall score is computed by the server, never copied from the model.
  • Consistency mode re-runs the judge up to five times and marks results unstable when scores swing.
  • Production basics: typed API, size limits, per-IP rate limiting, request IDs, JSON logs, token and latency metadata, Docker health check.
  • Errors map to clean 422 / 429 / 502 / 503 responses and never leak a stack trace.

RAG · Measured

docs-rag-eval

Question answering over the FastAPI documentation with numbered citations and honest "I don't know" answers, measured on 48 hand-labelled questions across 114 pages.

  • BM25 written from scratch in about 30 lines so IDF, saturation and length normalisation are visible and unit-tested; TF-IDF, embeddings and reciprocal rank fusion alongside.
  • Reports what didn't work: fusing two lexical retrievers scored below BM25 alone, because both fail on the same vocabulary-mismatch questions.
  • Citations are validated and CI fails if Hit@5 drops below 0.95 or MRR below 0.70.

MCP server · Built because I needed it

uk-visa-sponsor-mcp

A Model Context Protocol server and CLI that let Claude, or any MCP client, search the Home Office register of about 127,000 licensed sponsors and check a job offer against Skilled Worker salary rules.

  • Fuzzy company matching that handles Ltd / PLC / "&" and typos, and drops weak matches rather than showing false hope.
  • Salary rules encoded in one file with their sources, including new-entrant and pro-rated going rates.
  • Tested over a real stdio session: the tests start the server process and talk to it with the MCP SDK client. A weekly job checks the live GOV.UK register for format changes.

MSc project · Audited and rebuilt

The project where I withdrew my own results

My MSc thesis classified paediatric chest X-rays as normal or pneumonia. When I re-checked it, I found seven problems, including image-level splits that leak patients between train and test. Rather than keep quoting numbers I couldn't stand behind, I wrote up the audit and rebuilt the pipeline.

  • Patient-level 70/15/15 split with an automatic leakage check, and class weights for the ~73% pneumonia imbalance.
  • Sensitivity-first evaluation: a threshold chosen on validation for ≥95% sensitivity, applied once to test, reported against the majority-class baseline.
  • Grad-CAM to check the model looks at the lungs, not text markers, plus a FastAPI /predict endpoint and Docker image.
  • TensorFlow / Keras 3

02 · Research

The failures that accuracy alone doesn't catch.

Zenodo · May 2026 · DOI 10.5281/zenodo.20102941

AI Model Performance in CV Generation and Consistency Testing: A Practical Six-Dimension Evaluation Framework

Testing four models on a simple task, turning degree transcripts into a CV, I found the most dangerous failures were invisible: sections quietly left out, contact details and projects invented, and no model ever warning the reader that something might be wrong. The paper proposes six dimensions to measure that, each scored 1 to 5.

  1. 01Completeness
  2. 02Contextual utilisation
  3. 03Factual accuracy
  4. 04Confidence calibration
  5. 05Consistency
  6. 06Specification adherence

Finding 1 · Prompting

5→1

"Fill in ALL sections completely" dropped DeepSeek's factual accuracy from 5 to 1: it invented a phone number, email, GitHub profile and three projects.

Finding 2 · The MISSING instruction

5/5

Telling models to write "MISSING" instead of guessing kept factual accuracy at 5 for all four models. ResuMetric and sixdim-eval both build it in.

Finding 3 · Calibration

2/5

Confidence calibration was the universal failure: 2 out of 5 in all three sessions. Models rarely tell the reader what is uncertain.

Limitations, as stated in the paper's repository: scores come from a single annotator on a small number of tasks, so they show patterns rather than a statistically robust ranking. The judge-agreement tools in sixdim-eval exist to address that.
